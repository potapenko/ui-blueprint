## Required next bootstrap outcome — proposal, NOT implemented authority

The new direct user instruction requires URL of an existing authorized page plus
an explicitly selected component, without hand-prepared JSON or runtime IDs. Root
will register/assign the full implementation after this reconciliation. Minimal
compatible proposal (syntax illustrative until registered):

`uiblueprint web observe --url URL --component CSS_SELECTOR [--browser EXISTING_CONNECTION]`

1. **Browser input:** use an explicitly chosen already-authorized browser connection,
   or the sole preselected trusted connection from the caller. A URL cannot create
   that capability. If no connection provider exists, report connection-required;
   if several are available without selection, refuse ambiguity. No process/profile
   scanning, browser launch/reconfiguration, installation or app integration. The
   exact existing connection provider is a real required Core/caller integration
   boundary, not something supplied by Collector::attach. It must be named in the
   next contract/packet; do not default to a guessed port or browser.
2. **Page selection:** bounded typed target inventory over the chosen connection,
   exact caller URL match among permitted page targets. Zero→unresolved, multiple→
   ambiguous, no first-match/title/substring choice or navigation. Derive actual
   Target/frame/loader/document metadata; URL and selector are untrusted data,
   never executable text or logged raw private values. Credential/unsupported URL
   handling follows privacy/transport policy. Define URL normalization/fragment
   equality explicitly before code, preserving this consumer's SPA URL selection.
3. **Component selection:** explicit bounded light-DOM selector from the caller,
   exactly one current element; no fuzzy label/coordinate inference. Existing
   select-ids.js can cover literal DOM IDs, but general CSS-root selection is NEW
   registered semantics and needs bounded traversal/uniqueness, not unbounded
   querySelectorAll followed by truncation. No app IDs need to be added. Keep current
   frame/shadow/OOPIF boundaries unless separately authorized. Obtain backend ID
   from the actual selected object, preserve source document identity, and reject
   navigation/remount/ambiguous/incomplete selection before collection.
4. **Binding and observation:** derive only caller-scoped nonce locally; all browser
   IDs come from source. Revalidate exact URL/page/frame/loader/document/root at
   handoff, then use existing trusted TargetLease, WebSetup/WebSelection,
   RuntimeHost::attach_web/submit_web_observe and Collector::observe_rooted with its
   verify_target/verify_document/verify_rooted chain. Keep original objects through
   collection/publication; no stale repair or second graph/JS geometry. Generate
   canonical request/connection internally, invoke existing Rust analysis, report
   original coverage/unknowns. Define any URL change refusal in the new contract;
   do not silently weaken current parent/worker/identity/lifecycle guards.
5. **Owners/contracts:** Core owns CLI arguments/help/preparation entry and bounded
   control-plane metadata handoff (crates/cli/src/{arguments.rs,connection.rs,observe.rs}).
   Web owns reusable target/selection preparation using existing
   plugins/web/src/transport/{mod.rs,operation.rs}, cdp/session.rs::Client,
   collector/{io.rs,bootstrap.rs,select-ids.js}; current Binding/InitialScope/RootSeed
   in collector/mod.rs are the integration points. Host web_config.rs/worker_web.rs
   may need an explicitly scoped selection variant, never relaxed authority checks.
   Root must register the additive CLI preparation/Web selection contract under
   CLI18 OBSERVE/BOUNDARIES/IDENTITY/D02/D05 before those protected owners are edited.
   Distribution then exposes the resulting entry, not another separate engine.
6. **Required focused proof:** offline help; missing/ambiguous browser and URL;
   duplicate component/no match/quota/deadline; navigation, frame change, remount;
   sensitive/invalid input and sanitized diagnostics; unchanged app state, cleanup,
   no launch/profile modification; owned F01 URL+component→real canonical Observe
   and Rust geometry. Finally consumer retries Director using that new shipped
   command, without JSON/IDs/manual extraction. Existing requested/source limits
   remain explicit; a refusal is not a successful observation.

This is a finite code-owner dependency/design, not permission to implement it here
