## Narrow provider proposal (requires implementation selection)

Use existing canonical Intent::SetChecked{value:bool}, InputModality::Setter and
DOM source identity for a native HTMLInputElement whose current type is checkbox.
Do not advertise custom ARIA-checkbox/radio/pointer/keyboard support from role alone.
Chromium145 [HTMLInputElement IDL](https://raw.githubusercontent.com/chromium/chromium/145.0.7632.6/third_party/blink/renderer/core/html/forms/html_input_element.idl)
exposes checked as a writable boolean and indeterminate separately. This is API
shape evidence, not runtime permission or provider qualification. No code copied.

Fresh resolution must independently validate exact target/session/frame/loader,
original backend object connectivity/ownerDocument and requested authorized scope;
read current native checkbox type, enabled state, checked/indeterminate and actual
native checked setter availability. Produce canonical reported Resolution Evidence
bound to the fresh pre-state Observation; never promote cached Current flags.
Unsupported type, missing setter, unknown precondition or lost binding refuses
before parent effect permit. Native property accessibility is not mutation authority.

After the actual one-use Core/host permit, one fixed isolated native setter call
sets checked to the requested bool on that SAME held object. Recheck binding and
required state in the dispatch turn; no toggle, substitute selector, focus/scroll,
synthetic pointer/keyboard or fallback. No injected input/change events are hidden
inside this Setter claim. A direct property result does not establish framework/
application applied state. Already-equal bool must not be toggled; canonical delivery/
no-op accounting must follow Core's returned lifecycle contract, not an invented rule.

Verification performs one bounded explicit read of the same source object after
possible delivery, returns actual Checked with fresh canonical Observation/Snapshot
and unchanged target binding. Success requires actual requested boolean; missing,
mismatch, stale binding or timeout cannot pass. Parent Possible receipt survives
loss/cancel after permit; no retry/rollback promise. If a fixture business outcome
is later required, it needs an explicit independently observed predicate, not the
setter callback or generated event count. Setter alone is not full B02/user input.
