## Concrete product findings and finite outcome

**Exporter integration defect:** `crates/export/src/compile.rs::prompt` repeats
full serialized components for `component_table` and `state_and_action_table`, plus
verbose dimensions. Required self-contained output does not imply unbounded model
input. Expected: an unchanged real-form prompt can be submitted, or compatibility
limits are reported truthfully before a ready-for-ImageGen claim. Actual: successful
six-file package followed by HTTP400 for both actual forms. Reproducer: replay each
saved CLI argument array, submit its literal prompt with its clean crop. The CLI
success itself only claims package_written, so this is not a false CLI receipt.
No exporter repair was authorized or performed in E04.

**Sheet-plan inconsistency:** the same function supplies all selected sheets,
including G01, to `detail_views`; `prompt-template.txt` instructs rendering them as
enlarged details. A one-general-sheet package thus contains a contradictory detail
instruction. ImageGen invented details in both runs. That observed output does not
prove a unique causal mechanism, but the source/template mismatch is reproducible.

**Source/acquisition boundary:** imported-reference preparation is manual supporting
work. This experiment does not prove the normal browser→Observe→export path, role
normalization completeness, production source-build identity, viewport-wide fidelity
or independent acceptance. CSSOM values are API reports, not image-derived CAD facts.

**Generator deviations:** Director omits/misbinds real controls/state; both outputs
ignore requested output pixels and full dimensions/ID readability requirements.
The second attempts demonstrate that a caller can obtain an illustration after
preparing smaller input; they do not establish that current product prompts are
usable unchanged or that images are ready for exact marketing claims.
