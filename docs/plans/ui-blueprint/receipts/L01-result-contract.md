## Decision and consumer outcome

The exact records, tags, optional fields, validation layers, CLI syntax, compatibility
matrix and migration order are in
[schema.md](../../../development/schema.md#l01-analysis-result-contract).
This replaces the older indefinite proposal; no real product-intent fork was found.

- Add schema-owned AnalysisDocument0.2.0 for geometry_query, evaluation_input,
  measurement and geometry_check. Reuse existing canonical Snapshot/Context and
  geometry/evidence types. Core Document/Artifact/SchemaVersion0.1 and generated
  core schema remain unchanged. Outer analysis version is distinct from the
  unchanged embedded source Context version; no automatic version promotion.
- Factual GeometryQuery contains relation/anchors/units/kind/scope/targets and
  explicit applicability, with no expected/comparison/tolerance/expected_from.
  MeasurementResult carries known quantity/full result Space/details/all evidence
  or typed unknown/attempted evidence/no value. GeometryCheckCase additionally
  carries the actual Expectation, bound evaluation and unchanged Finding leaf.
- EvaluationInput binds Snapshot ID/revision/full Context, exact result Space,
  ordered canonical transforms and optional observed conditions/evidence. Only
  existing source Observations can satisfy references; no supplemental registry,
  inferred conditions or Snapshot edits to manufacture evidence. Multi-observation
  per-field conditions require a separate finite follow-up rather than evidence loss.
- Schema validates shape, context, evidence and declared outcome consistency;
  engine remains the sole arithmetic owner. An explicit engine verification API
  recomputes imported results, including full evidence/details/unknown reason.
  Merely matching units or attaching a transform is never arithmetic verification.
- `measure --json` gains canonical0.2 output; pure `--query` needs no Expectation.
  Existing measure-with-expectation remains a faithful compatibility wrapper.
  `check --json` retains existing0.1 behavior; `--result-version 0.2.0` opts into
  full converted/conditional results. Additional input uses bounded `--evaluation`.
  Exits remain0/1/2/3/4/5; factual measurement gains no normative pass/fail.
