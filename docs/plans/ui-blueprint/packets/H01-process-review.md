## Mandatory criteria

1. Exact absolute bounded SpawnSpec/argv/env and one owned child: no shell, inherited
   environment collection, user PID targeting or unregistered descendants. Partial
   failure cleans only acquired resources; errors do not leak private payload/path.
2. FD mapping0/1/2→null and3/4/5→protocol/fatal is robust to low-FD/source-target
   collision; unrelated descriptors cannot leak. Parent flags and borrowed/owned
   FD lifetimes are correct. Closed peers cannot unexpectedly kill the parent.
3. Nonblocking byte IO and max36 fixed poll entries preserve Bytes/WouldBlock/Closed,
   zero/overflow/error cases and bounded relative waits without hidden deadline
   renewal. No production growable Rust graph/control storage behind fixed claims.
   Name C/OS allocations honestly, not as measured Rust/RSS-cap proof.
4. PID ownership/reap state is real and exclusive; terminate is not confirmed exit.
   Repeated calls, reaped or lost wait ownership cannot signal a reused/unowned PID.
   Drop is not allowed to masquerade as confirmed cleanup. Core must retain grants
   and quarantine until actual facts permit release; no user process cleanup.
5. Worker-only core-dump/main-stack setup, actual-thread stack query and checked
   watchdog creation request preserve adopted ceilings. Creation request is not
   actual extent proof; the caller checks it before untrusted work. Platform/compiler
   limits are explicit; no silent larger cap or unverified universal rounding rule.
6. Fatal status uses a fixed64-byte best-effort nonblocking operation then immediate
   exit without Rust allocation/format/log/panic/unwind/retry. Missing status is not
   invented quota attribution. Unsafe pointer/layout/C-handle/thread/FD invariants
   are valid at each call; don't weaken other crates' unsafe policies.
7. Scope-specific tests and evidence really cover claimed paths/owned-resource
   cleanup, distinguish phase-specific checks and have exact source/shared inputs.
   Do not require real Core watchdog/allocator/publication or live platforms here;
   those are required later integration gates, not already delivered by OS tests.
