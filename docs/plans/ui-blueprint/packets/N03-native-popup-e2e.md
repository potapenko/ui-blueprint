# N03 — продуктовая Native popup-action цепочка

Самостоятельная shipping_product задача по исходному PLAN.UIB@1 / COMPLETION
Native E2E. Q01 на94724df подтвердил отдельные form/capture/geometry/close slices,
но popup открывался/подтверждался CUA setup: целая product popup-input composition
не доказана. Довести именно этот outcome, а не повторять отдельные куски.

Полный цикл в одном чате: определить нужное по источникам, свой короткий план,
необходимый код/fixture/harness, tests/actual own runtime, исправления, docs,
commit+push и финальный результат. После плана реализация разрешена без root
микропоручений. Не создавать подагентов/другие чаты. Если API уже достаточен,
не менять его ради активности: квалифицировать реальную целую цепочку.

## Результат и нормы

Через shipping Native API/CLI: точное одноимённое окно → открыть own popup →
measure доступных свойств → разрешённый выбор/подтверждение с independently
observed result → resize/local geometry diff → close/retired ref refusal →
compare-пакет. Setup/публикацию bindings отделять от проверяемого product input;
CUA не подменяет доставку, а может независимо наблюдать результат.
Конкретная fixture-семантика задаёт whether selection closes popup; порядок
оформить без ложного утверждения, что закрытый popup продолжает жить. Не создавать
лишние контролы, если текущий fixture позволяет доказать исходный сценарий.

Spec route: AGENTS → specs/README → product/README → NATIVE@2/ACTIONS/FORMS/
IDENTITY/LIFECYCLE/PROJECTIONS/GEOMETRY/PRIVACY/CACHE/MODEL/BOUNDARIES,
EXCHANGE@2; NATIVE-SESSION@2/CLI@16/CLI-ACTIONS@3, CLI-EXPORT@2/G12/G13/ANALYSIS
по consumers; acceptance/COMPLETION@1 Native E2E и NATIVE-PILOTS/PILOTS/GOLDEN
и explicit closure; D02@2/D03@4/D04@1/D05@4/MEMORY@2/WORK@1/Native
acquisition@2/D06@1/D07@5, RUST/DEV.RUST@2 и зависимости.
Mode Restore исходного сценария с delegated ROADMAP technical representation.
Изменение private scope/CLI представления зарегистрировать до кода, сохранив
normative authority, legacy wire/canonical meanings и обычные paths.

Popup и parent — разные Surface/поколения, owner/anchor с реальным источником.
Никакого поиска по title/rect/order, silent whole-app expansion или новых refs
из эвристики. Если actor закрывает себя, independently held result не заменяется
другим похожим элементом. Не склеивать identities и не выдавать старые данные
за свежие. Исчезновение actor/Surface и verification результата трактуются по
реальным contracts, а не ради Execute0. Held refs не переживают свой session/reap;
каждый фактический ввод требует existing parent permit и соответствующего owner.
Unknown effect не ретраится. Semantic AX input не становится physical pointer.

V02 FillSecret/one-use file/trace/secure classification и SAME Surface public-result
ограничение PROTECTED сохраняются. Popup integration не ослабляет protected-input
boundary. Не менять secrecy protocol/nonce/quotas для удобства cross-surface формы.
Если новый public/shared model действительно необходим, установить минимальный
source-backed dependency и legitimate contract delta, не создавать shadow graph.
