## Результат
Одна диагностическая интеграция и одна сборка на ревизию приложения обслуживают все запросы. Агент указывает окно и элемент, область или всё дерево; Blueprint получает **новые runtime-данные**, разрешает выбор, вычисляет геометрию и возвращает источник, время и полноту. Новые code edits, rebuild, ручной Xcode Export и отдельный чат для каждого элемента не нужны.

Механизм доступен во всех destinations и presentation roots. Динамические элементы входят в следующий сбор автоматически после появления. Закрытые экраны не строятся ради измерения; после обычного открытия работает та же сборка. Геометрия ещё не созданного элемента не выдумывается.

Live-запрос по умолчанию начинает сбор после поступления запроса. Saved Snapshot — явно исторический режим. Несколько связанных измерений используют один новый sample. Полное дерево доступно для discovery/обзора; scalar-запрос не обязан передавать его целиком агенту или сохранять на диск.

## Неизменные условия приёмки
1. Настоящие SwiftUI containers/leaves и frames, а не только метки выбранных controls или NSHostingView.
2. Свежие данные после resize, navigation, popup open/close, scrolling, смены данных, remount и restart.
3. Одна интеграция для всех потребителей; новое обычное View или runtime occurrence не требует специального collector.
4. Точные identities, units, spaces, transforms и coverage; отсутствие данных не заменяется старыми числами.
5. Bounded execution, корректная конкуренция и сохранение поведения приложения.
6. Работающий установленный инструмент и регрессии жизненного цикла, а не только успешный экспорт.

Обычные mounted-кейсы обязательной матрицы должны возвращать числа. `unsupported` для такого кейса оставляет поддержку незавершённой; хороший текст ошибки не считается выполнением задачи.

## Порядок исполнения
| Этап | Работа | Проверяемый выход |
| --- | --- | --- |
| E0 | Закрепить контракт запроса, inventory всех экранов и обязательную матрицу. | Цель не подменена названием библиотеки или частичным списком меток. |
| E1 | Завершить Xcode reference capture; квалифицировать программный runtime-вызов кандидата на общей fixture. | SwiftUI leaves и новые frames после resize/dynamic changes в одном процессе; известны формат и effects. |
| E2 | Зарегистрировать конкретные contract deltas; реализовать request lifecycle, normalization и Rust query. | Один installed find-and-measure работает повторно; live и saved различены. |
| E3 | Native-владелец подключает механизм ко всем Mac destinations/presentations. | Одна сборка проходит полную state-change последовательность без source edits между запросами. |
| E4 | Квалифицировать те же protocol/semantics в Phone/Tablet. | Реальные iPhone и landscape iPad Simulator flows; physical device имеет отдельный результат/prerequisites. |
| E5 | Privacy/concurrency/compatibility review, Release exclusion, installed skill и выпуск. | Проверенная версия, воспроизводимый вызов, support matrix и регрессии. |

Xcode GUI capture — проверка источника E1. Итог не требует ручного Capture/Export для каждого измерения. Импорт одного файла не завершает E2/E3. Именованные диалоги — regression cases общего механизма, не отдельные поставки.

Выбор backend делается по общей матрице после ограниченного E1. Повторяющийся дефект исправляется в общем adapter, не новым reader на каждый экран. Два сопоставимых отказа без улучшения требуют изменения гипотезы по данным, не косметических вариантов или увеличения лимитов.

## Spec Basis и изменения
Вход через [реестр](../specs/README.md): SWIFTUI-PROBE@3, WINDOW-PROBE@1, BOUNDARIES@1, NATIVE@5, MODEL@1, IDENTITY@1, GEOMETRY@2, PROJECTIONS@1, EXCHANGE@2, PRIVACY@1, LIFECYCLE@1, CACHE@1, CLI@21 и их выбранные зависимости. Native: specs/README → developer control plane → swiftui-geometry@4, lifecycle/Release; platform-shells r8.

Требование пользователя — повторяемый live-запрос. Наблюдаемая реализация — частичные SDK/AX/cache-reader и ещё не завершённая native Xcode qualification. Предложение плана — единый request pipeline; ни один кандидат не объявлен полной реализацией.

Режим реализации — Evolve диагностического API/сбора/интеграции. Перед source edits зарегистрировать выбранные семантические дельты. Сохранить существующие SDK/AX/Web/Compose/GPUI, core0.1/analysis0.2 и saved records. Xcode source не переименовывается в существующий namespace SDK.

## Владение и write set
Эта редакция меняет только данный план и пять его листьев. Исходники, active specs, установка и чужие процессы не изменяются.

Blueprint владеет конкретным adapter/importer, SDK при доказанной необходимости, узкими CLI/engine изменениями, fixture/bridge tests, выбранными specs/skill/install/package inventory. Точные source paths закрепить после E1; не создавать инфраструктуру всех альтернатив сразу.

Native-чат владеет app-level hook/ingress, dependency pin/target membership и всеми настоящими измерениями. Общие native файлы согласуются с действующим владельцем. Здесь регрессии инструмента выполняются на project-owned fixtures.

UI, бизнес-модели, авторизация, платежи, persistent stores и deployment floors не меняются ради измерения. Обычные Release-схемы и native publication gates сохраняются. Независимое ревью проводится только в реально разрешённом объёме.

## Завершение
Закрывать по обязательным сценариям установленного инструмента на реальном приложении. «Есть дамп», «собрали библиотеку», «135 меток», «понятный отказ» и опубликованный tag не заменяют этот результат. Непроверенный platform profile остаётся явным; отсутствие физического устройства не задерживает работающую Mac/Simulator поставку.
