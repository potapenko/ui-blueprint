# K01 storage implementation proposal — awaiting D05

Status: design only, not adopted policy or an implemented cache. Consumer: Integration's D05 decision, then a bounded K01 implementation packet. Numerical limits and enforcement must be pinned before source changes.
Requirement basis: [CACHE](../specs/product/cache.md), [LIFECYCLE](../specs/product/lifecycle.md), D03/D04/D05 and their selected closure. The ownership/API/eviction choices below are **proposals**, not new product authority.
Observed: [pure replay](replay.md) exists; [owned sizing](../../tests/bridges/resources/README.md) counts canonical capacities; [working evidence](../../tests/bridges/resources/working-memory.md) separates parser/framing/session phases. Neither study establishes an RSS cap or a universal decoder bound.

## Proposed owner and API

`engine::cache::CacheStore` exclusively owns canonical payloads for sessions inside one subordinate quota domain. The host is the **single aggregate retained-quota owner**: it assigns nonduplicated Store allowances before creation. One local Store may hold several sessions; if D05 selects a per-session worker, each worker uses the same API with one session and its assigned allowance, not the entire host cap. Store usage is local; host reservations enforce the cross-worker aggregate. This fixes ownership without selecting process packaging.
No `Arc`, reference-counted shared snapshots, hidden clones, persistence, collector, allocator or timer thread in the library. The API takes canonical values/borrows, explicit limits/time and an opaque host work permit; it has no PID, socket, child-process or worker-lifecycle dependency.
Use fixed-capacity `Vec<SessionSlot>` and per-session `Vec<RevisionSlot>` initialized at creation, never grown by admission. Slots contain canonical Snapshot **by value**, scalar generation/admission sequence/expiry/invalidation metadata and an owned channel-partition vector. Unused slot capacity stays charged. Caller-supplied maxima make lookups finite; no guessed defaults.
Each occupied session owns a small header (`session_id`, target identity/generation, plugin identity/version), limits, slot storage and counters. Slot/generation handles contain integers only and are not wire/backend/action refs. Counter overflow refuses new admission, never wraps. Full-key lookup scans bounded occupied slots; no BTree/Hash indexes, duplicated string-key table or source-node index in slice A.
Proposed non-wire signatures (names provisional; canonical payloads unchanged):
```rust
open_session(header, session_limits, creation_permit) -> Result<SessionHandle, CacheError>
admit_full(session, partition, snapshot: Snapshot, now, work_permit) -> Result<RevisionHandle, Rejected<Snapshot>>
read(key: SnapshotKey<'_>, now) -> Result<StoredRead<'_>, CacheError>
apply_delta(base: RevisionHandle, delta: &Delta, result_id: Id, now, work_permit) -> Result<RevisionHandle, CacheError>
invalidate(session, context: &Context) -> Result<(), CacheError>
expire(session, now) -> Result<ReleasedCharge, CacheError>
detach(session) -> Result<ReleasedCharge, CacheError>
usage() -> StoreUsage
```
`StoredRead` borrows `&Snapshot` plus separate invalidation/disposition metadata; it does not rewrite canonical Observation freshness. Rust borrowing prevents mutation/eviction while a read is live. There is no API returning an uncharged owned clone. A consumer can still explicitly clone a public Snapshot: the host must reserve and account that copy; borrowed reads are not a process-wide allocation sandbox.
`now` is an explicit same-domain monotonic host sample; deadline arithmetic/regressions reject on error. No engine clock read. The host invokes expire at its owned lifetime deadline and detach on teardown; no UI polling is introduced. Expiry/TTL never proves current UI state.

## Full keys and separate owners

| Owner/key | Exact contents and protection |
| --- | --- |
| Snapshot lookup | Canonical Context: schema version, session ID, target ID/generation, complete Surface IDs/generations, scope, projection, selected fields, plugin ID/version, environment revision; **plus** declared collection channel partition, Snapshot ID and revision. Context set ordering uses canonical compatibility, not source titles/coordinates. Keys borrow canonical records for lookup; their IDs/strings are already owned inside each Snapshot/header. |
| Revision family | Same full Context + channel partition, excluding Snapshot ID/revision. `max_revisions_per_family` applies here, with a separate total slot bound so many scopes cannot evade quotas. No joining different targets/scopes/fields/projections/environments. |
| Channel partition | Explicit canonical `Channel` set from the caller's collection request/response ownership; normalize once and own/count its Vec. Do not infer requested channels from the observations present: failed/partial/history channels differ. Bare imported snapshots need an explicitly supplied stored-data partition; there is no automatic live-channel inference. Partition is private cache metadata, not another serialized graph. |
| Derived relations | Separate owner keyed by exact retained revision handle/generation, full canonical geometry request/Expectation, result Space, supplied transforms and observed conditions/evidence. Store the complete engine measurement/evidence/details; no reuse merely by element names or units. Observed graph `Snapshot.relations` remain canonical Snapshot data, not this spatial-result cache. |
| Checks | Separate owner keyed by exact retained revision handle/generation, full Expectation (including expected_from/tolerance/applies_when), and complete evaluation context. Store canonical Finding plus complete engine result/evidence, never just boolean success. Missing shared result/context records still prevent corresponding wire output; internal ownership does not resolve that gap. |

Derived keys own their parameter copies, with every Vec/String/Box charged. Compare full typed values rather than an unproved hash-only match. Slice A implements Snapshot storage; derived owners get their own later finite slice before full K01 acceptance, not placeholder modules or results stuffed into Snapshot storage. Any future index/sharing optimization needs an explicit allocation/release inventory and affected checks first.

## Allocation inventory and formulas

Let `H(x)` be exhaustive canonical owned heap capacity (String capacity, Vec capacity×element layout plus initialized elements' nested heaps, Box payload+descendants, Option/enum/array live contents). Use checked sums/products; ZST Vec capacity is not an allocation. The existing diagnostic walker demonstrates this accounting, but is **not yet a production API**. Integration must select its shared production owner; proposal: extract/reuse it in `schema::owned_size` as also proposed by Integration, without changing DTOs/validators or a copied second field inventory.

| Retained allocation | Exact charge/release rule |
| --- | --- |
| Process Store/session table | Root fixed layout once at host owner; session-slot Vec actual capacity×slot layout, including vacant slots. No allocator headers/rounding, thread stack or OS RSS claim. Slot generations/counters are inline, not extra allocations. |
| Session | Header ID/identity/plugin strings, limits/clock-domain storage, revision-slot Vec actual capacity×slot layout; later separate relation/check slot Vecs and their own heap payloads. Detached session drops all of these heaps; vacant process-slot capacity remains charged. |
| Revision | Slot inline layout already contains Snapshot/metadata/partition Vec headers. Add `H(snapshot)` and partition Vec backing; never add Snapshot inline a second time. Every full revision is independently owned; no assumed deduplication of equal strings/nodes. |
| Canonical descendants | Include context/IDs/source_state, node properties/native roles/children/extensions/source declarations and value strings/lists/geometry, Observations/coverage/evidence, relations, component mappings, surface records, focus/selection/composition, captures and transforms. Nested capacities and unused capacity count, not only serialized length or live nodes. |
| Keys/indexes/derived values | Slice A has no separately allocated lookup indexes or cloned Context keys. Derived parameter copies, result/evidence/geometry details, invalidation metadata if heap-backed and any later indexes require their own exhaustive accounting. Never assume map-node cost is just key+value size. |
| Pixels/external objects | `payload_ref` string and CaptureFrame metadata count here; referenced buffers/files/helper/SDK state do not. Slice A has no pixel dereference or lease API and does not keep an image fresh/alive by retaining metadata. Actual pixel retention needs its own bounded host owner. |

For an occupied session: `session_charge = size_of(SessionValue) + H(header/domain) + revision_slots.capacity * size_of(RevisionSlot) + Σ occupied_revision_heaps + derived_slot_backing + Σ derived_heaps`.
For the Store: `store_charge = size_of(Store) + session_slots.capacity * size_of(SessionSlot) + Σ(session_charge - size_of(SessionValue))`; SessionValue inline is already inside SessionSlot. Empty slots still cost backing storage. Eviction frees only entry-owned heaps, not reserved slot capacity. Reports distinguish committed usage, reserved capacity and outstanding working reservations.
These formulas bound the chosen owned-capacity metric only. Realloc overlap/allocator internals/RSS require D05's separate enforcement; inspecting capacity after allocation cannot enforce a peak limit retroactively.

## Admission, working ownership and limits

D05 must supply explicit finite `max_sessions`, `max_snapshot_slots_per_session`, `max_revisions_per_family`, per-entry/per-session/process retained-byte limits, maximum retention duration, and working-byte/admitted-operation limits. Later derived owners need distinct relation/check entry and byte ceilings. No number or enabled default is selected here. Creation refuses configurations whose fixed slot backing already exceeds a cap; use checked layout arithmetic and fallible explicit slot reservations. Existing validator/replay allocations still require the host enforcement below.
Propose a fixed retained-pool allowance carved out by the host at Store creation, separate from working/decoder/framing/Completion allowances. Store enforces session and aggregate retained use within that allowance. Host checks overlapping reservation domains against its chosen global metric. If a worker allocation ceiling already contains its retained allowance, the retained quota is a nested restriction, not additional physical memory counted twice. If Integration chooses dynamic transfer instead, it must define an atomic charge-token transfer API before implementation; an encoded counter is not that API.
An incoming decoded Snapshot already belongs to a charged caller/Completion. Measure its actual capacities without cloning, validate using existing canonical validation, prepare an eviction/admission plan, then move ownership into a free/reclaimed slot. On rejection return the original owned Snapshot to its charged caller (or drop it explicitly); never zero a caller charge while its value survives. `ObservationSession::complete/detach` transfers channel payloads into Completion, so pending_encoded_bytes=0 is not release of those payloads.
Proposal: deterministic oldest-admitted eligible entry eviction within the requesting session, satisfying the per-family revision bound first. Reads do not secretly update LRU state. Do not automatically evict another session under aggregate pressure; refuse with resource_limit/busy and preserve it. Eviction is retention loss: a later base lookup gives resync_required, never a UI deleted event.
Build/validate a candidate and calculate checked post-commit charges **before** evicting or publishing. Protect the replay base until success. Recoverable validation/quota/base/identity refusal or fallible slot-allocation failure leaves old entries/counters unchanged; this does not promise recovery from a process abort. Duplicate full key+identical record can return the existing handle; conflicting reuse refuses/resyncs rather than replacing immutable history. Retiring a source revision also removes its dependent derived entries atomically.
Replay needs a separate reservation while base, borrowed Delta, candidate clones, observation copies and temporary BTreeMap/BTreeSet/Vec storage coexist. The existing pure replay and canonical validators allocate internally; they cannot be made peak-bounded by charging only the final Snapshot. D05 must name the actual enforcement/justified bound and owner before storage calls them. No multiplier is inferred from the measured parser samples.
The [Integration draft](../plans/ui-blueprint/receipts/D05-policy.md) at `8103675` proposes reusable quota workers; D05@1 remains unchanged. It is not selected by this handoff. Standard serde/container OOM is not promised as a recoverable replay Result. If the host chooses isolation, worker loss can lose its Store: the host must map lost bases to resync, preserve already validated/redacted completed-channel buffers outside that failed owner, suppress late results and preserve other sessions. Only actual destruction/owned-worker cleanup releases its allowance; retained host Completion buffers keep their own charge. These host proofs precede live acceptance and are not implemented by K01.
Other separate reservations: session/slot creation; decoder input+scratch+decoded DTO including rejected input; framing reader/queued/producer buffers; encoding output while DTO remains; derived request/result copies; exported/returned Completions; host timers/queues/control storage. Charge a physical owner once, but reserve every phase that may overlap. Admission transfer, eviction/drop, failure and detach have explicit release points; immutable borrows allocate nothing.

## First implementation slice, dependencies and tests

Slice A after D05: real session/aggregate Snapshot store, explicit full-key reads, immutable admission, atomic replay admission, deterministic scoped eviction, invalidation, expiry and detach. No storage of raw wire/pixels, polling or disk history. Caller receives recorded data with its original coverage/times and separate cache disposition. Expired/evicted/missing bases require resync; invalidated data cannot satisfy current-required reads merely because TTL remains. No automatic recollection. Full K01 still requires the separate derived-cache owners and lifetime integration.
Minimal proposed writes: `crates/engine/src/cache.rs` (split only if needed), export in engine lib.rs, `crates/engine/tests/cache.rs`, this doc/receipt; replay changes only if a pinned working-reservation handoff requires them. Integration separately owns the canonical accounting extraction and host budget/enforcement interface. No CLI/plugin/schema-validator changes or new dependencies are silently included.

| Focused acceptance | Required falsifiable result |
| --- | --- |
| Quota/overflow | Exact under/at/over capacity boundaries, unused capacity, fixed vacant slots, checked multiplication/addition and allocation refusal; rejected admission leaves contents/counters unchanged. |
| Keys/isolation | All Context dimensions plus channel partition and revision; same labels/IDs across sessions cannot collide. Reopening a slot/session changes its generation; no stale handle alias. No cross-session eviction. |
| History/unknown/privacy | Known→unknown/unsupported/redacted/false/empty remains exact after replay/storage; outside-fields history never becomes current. Declared sensitive canary never persists; redacted and known empty remain distinct. Use existing validation, no replacement validator. |
| Replay/eviction | Independent full/delta equality; atomic failure and old base intact; evicted base→resync with no invented removal; dependent derived entries retire with source revision. |
| Lifecycle/accounting | Borrow prevents eviction; explicit copied reply/Completion remains charged until its owner drops it. Eviction retains slot-backing charge; detach releases only its session heaps; other sessions/leases remain intact. |
| TTL/invalidation | Supplied monotonic boundary/overflow/domain checks; expiry/detach cleanup; TTL never upgrades Observation freshness and invalidation never triggers collection. Captured metadata keeps original Observation. |

Exact handoff to Integration: select production accounting API/metric; bind retained/session/global numbers to this slot layout; choose host reservation/transfer and decoder/replay enforcement covering rejection; define lifetime clock/deadline cleanup ownership and explicit channel partition handoff. None needs another universal profiling campaign. Five protected review findings and measurement/result-space/external-context wire gaps remain open, not repaired by this proposal.
